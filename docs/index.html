01 / ARCHITECTURE

一個請求怎麼走完

dbo.Products
API 層　Data Annotations 擋掉空白品名、負數價格；路由的 {id:int} 讓 1 OR 1=1 這種值根本進不來。
DB 層　NOT NULL、CHECK (Price >= 0)、CHECK (Stock >= 0)。就算有人繞過 API 直接呼叫 SP，資料一樣不會壞。

03 / STORED PROCEDURE

五種操作，一個入口

API 不寫任何 SQL 字串，只告訴 SP「要做什麼」和「用哪些值」。每個端點對應到的呼叫如下：

HTTP@ActionSP 回傳
GET /api/productsLIST全部資料列
GET /api/products/1GET0 或 1 列 → 404 / 200
POST /api/productsCREATE新增的那列 → 201
PUT /api/products/1UPDATE修改後的那列，0 列 → 404
DELETE /api/products/1DELETEAffectedRows → 204 / 404
在 Demo 裡直接執行 SP 
CREATE OR ALTER PROCEDURE dbo.usp_Products_CRUD
    @Action NVARCHAR(10),
    @Id     INT           = NULL,
    @Name   NVARCHAR(100) = NULL,
    @Price  DECIMAL(10,2) = NULL,
    @Stock  INT           = NULL
AS BEGIN
    SET NOCOUNT ON; SET XACT_ABORT ON;

    IF @Action = N'CREATE'
    BEGIN
        INSERT INTO dbo.Products (Name, Price, Stock)
        -- 直接把新增的那列回傳給 API
        OUTPUT inserted.Id, inserted.Name, inserted.Price,
               inserted.Stock, inserted.CreatedAt, inserted.UpdatedAt
        VALUES (@Name, ISNULL(@Price, 0), ISNULL(@Stock, 0));
        RETURN;
    END
    -- LIST / GET / UPDATE / DELETE 同樣寫法……
    END;  -- THROW 前一句要有分號

    THROW 50001, N'Unknown @Action.', 1;
END

04 / SECURITY

同一個輸入，兩種寫法

刪除時如果把網址上的 id 直接拼進 SQL，有人送 1 OR 1=1 就能清空整張表。這個專案三道防線都有：路由型別、SqlParameter、預存程序。

字串拼接SqlParameter + SP
收到DELETE /api/products/1 OR 1=1
實際執行DELETE FROM Products WHERE Id = 1 OR 1=1路由 {id:int} 不符 → 404，SP 根本沒被呼叫
結果整張表被刪光資料不變
 
// ProductRepository.BuildCommand（節錄）
var cmd = new SqlCommand("dbo.usp_Products_CRUD", conn)
    { CommandType = CommandType.StoredProcedure };

cmd.Parameters.Add("@Action", SqlDbType.NVarChar, 10).Value = action;
cmd.Parameters.Add("@Id", SqlDbType.Int).Value = (object?)id ?? DBNull.Value;
cmd.Parameters.Add("@Name", SqlDbType.NVarChar, 100).Value = ...;

var price = cmd.Parameters.Add("@Price", SqlDbType.Decimal);
price.Precision = 10; price.Scale = 2;

06 / INSTALL

在自己電腦跑起來

  1. 取得程式：需要 .NET 8 SDK。Windows 用 Visual Studio 2022 開 ProductApi.sln；Mac 用 VS Code 或 Rider。 
    git clone https://github.com/Tai-Ju/aspnetcore-sqlserver-sp-crud
cd aspnetcore-sqlserver-sp-crud
  2. 準備 SQL Server
    WINDOWS
    Visual Studio 內建 LocalDB，連 (localdb)\MSSQLLocalDB 即可，連線字串不用改。
    MAC
    用 Docker 跑 SQL Server，再把 appsettings.json 改成 Server=localhost,1433;User Id=sa;Password=…;TrustServerCertificate=True。
  3. 建資料表與預存程序：在 SSMS、Azure Data Studio 或 VS 的 SQL Server 物件總管執行 
    database/01_schema_and_sp.sql
  4. 啟動：按 F5，或 
    dotnet run --project src/ProductApi
    開 http://localhost:5020 是連線版的 CRUD 頁，/swagger 是 API 文件。
常見問題
  • 出現 Cannot open database "ProductDb"：SQL 腳本還沒執行，或連線字串指到別台。
  • Mac 上 LocalDB 不能用，一定要改連線字串。
  • SP 改過之後，重跑整份腳本即可；用的是 CREATE OR ALTER，不會報已存在。
